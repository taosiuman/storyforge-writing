# C-screenplay — 小说转剧本子契约（v0.2.0 新增）

> 来源：`H:\storyforge-main\docs\products\INDEPENDENT-CREATION.md` §3「小说转剧本」
> （主基线；引文与判据均出自该节，未改写为更强表述）。基线表见 `SKILL.md` §来源与验证。

## 1. 输入

- 本地作品、导入文档或用户选择的章节范围；
- 目标剧本类型、篇幅、媒介、受众、改编自由度和禁改内容；
- 源 manifest、原文证据和用户锁定事实。

## 2. 生产链（严格顺序）

```text
源文解析与范围冻结
→ 事实 / 人物 / 场景 / 动作 / 对白提取
→ 改编 Brief 与删改原则
→ 场次/节奏/视角计划
→ 剧本场景生产
→ 连续性、格式与源文证据审校
→ 作者修改与批准
→ 不可变剧本版本 / 导出
```

**三态必须区分**（源文档要求「系统要区分忠实保留 / 合理改编 / 新增假设，让作者能追溯关键删改」；
下表**「要求」列是本技能的落地约定**，**非源文档原文** —— 便于执行，如与源文档冲突以源文档为准）：

| 态 | 含义 | 要求 |
| --- | --- | --- |
| 忠实保留 | 源文已有且必须保留 | 标 source mapping（文件 + 偏移/行号） |
| 合理改编 | 为改编目标而改动 | 标改动理由，可被作者复核 |
| 新增假设 | 源文没有、由模型补 | **必须显式标注**，不得混入"忠实保留" |

- **格式校验由确定性代码负责，戏剧改编由模型和作者判断**（不要把格式合规交给模型）。
- 关键删改必须可追溯（作者能查到"哪一段原文被改成了什么"）。

## 3. 完成判据

- 整部小说可分块处理并**保持 source mapping**；
- 角色/场景连续；
- 剧本格式可导出；
- 中断可恢复；
- **源文更新会使相关候选 stale**；
- **修改源小说不会静默改变已发布剧本**。

## 4. 工程边界（源自 §3.4 现行 UI 接入，2026-09-15）

- 正式入口 `/script/:pageId?`，以 `work` 查询参数绑定剧本 Work；**不提供派生世界路径**。
- 导入原作会建立**独立长篇 Work**，按原始偏移分成约 **20,000 字符**的连续章段，不截断、不叠加原文；
  再冻结为剧本来源。原作输入上限 **500 万字符**（文件解析仍遵守各格式本地大小限制）。
- 长篇、短篇与剧本作品库**分别按 Work 类型读取**；删除原作只删除该 Work，不连带删除剧本。
- 场景草稿按**稳定场次键 + revision** 保存；**不把数据库本地 ID 当作可移植草稿身份**。
- 拆分是整体事务（非法块边界不留截断场景）；复制/拆分同步 Scene Card；**合并限制同节拍**；
  重做 Beat/Scene Card 必须在**保存备份 + 作者明确确认**后替换下游；**已发布版本保留**。
- **未处理任务阻断发布**；供应商异常不自动重发；已记录采纳意图时恢复同一任务，不重复调用模型。
- 版本页提供不可变发布、历史版本选择、`Fountain`/`FDX`/浏览器打印；**历史版本差异与恢复为新草稿尚未开放**；
  **社区发行与视频生产不属于本次交付**。

## 5. 验证入口（引用，不代跑）

`R-SCREEN4-ui-integration`（拆分原子性、场次卡同步、失败收尾、草稿隔离、长原文分块、取消后迟到响应、
未知结果阻断发布、上游规划失效）· `screenplay-integration`（全 UI 人工生产/发布、候选人工编辑与排除项恢复、
作品库与删除隔离）· `screenplay-production`（电影/剧集/短剧与导出）。

## 6. 与其它子契约的边界

- 与 `A-longform.md`：剧本来源小说是**独立 Work**，不是长篇作品的派生；改源小说不得静默改剧本。
- 与 `C-post.md`：本契约到"不可变剧本版本/导出"为止，**不含**后期生成管线对接。
- 与 `S-data-envelope.md`：剧本产物同样受三注册表与证据分级约束。
